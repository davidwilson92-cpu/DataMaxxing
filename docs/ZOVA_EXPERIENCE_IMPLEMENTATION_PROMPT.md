# Zova experience implementation brief

Continue the existing Zova application. Read `ZOVA_CONTINUE_HERE.md`, the 13 September product audit, `ZOVA_PRODUCT_AUDIT_FOLLOWUP.md` and `ZOVA_CUSTOMER_EXPERIENCE_REVIEW.md`. Reproduce findings before changing their status. Preserve the existing branch's compatible security and persistence work. Do not rebuild.

## Outcome

Make “One idea. Every social. Still you.” visible in the customer's work: one stable idea, deliberately different platform versions, recognisable voice, safe review and clear outcomes. Preserve the Z mark, ink and purple palette and confident language. Reduce decoration in the working product. Treat industry leadership as a hypothesis requiring comparative customer evidence, not a completion label.

## Non-negotiable safeguards

Preserve PostgreSQL users/data, uploads, session continuity, encrypted connections, both Instagram login routes and reviewer access. Keep subscription enforcement disabled for testing. Keep final approval bound to the exact server-owned text, media, destination, settings and time. Never silently omit destinations or retry uncertain publication. No real posts, charges, grants, review submissions or production deployment. Validate using synthetic accounts and mocked providers.

## Work in reviewable increments

1. **Promise and first value.** Replace unsupported automatic-learning claims. Label signup honestly or carry an entered idea through authentication without exposing it in a URL. Show a labelled editorial example of one idea expressed differently for the four supported networks; distinguish captions from finished visual/video assets. Explain the testing offer. Make connection and voice setup optional, with a direct first-draft route. Preserve existing returning-user and OAuth flows.
2. **Stable Studio.** Give the current idea a persistent canvas separate from assistant conversation. Name it from real customer input. Keep versions, editor, preview and comparison together. Move analytics to its existing destination; show saved ideas without occupying the main canvas. Reduce composer density with optional source/format controls. On mobile provide explicit Conversation, Draft and Preview modes, with reachable navigation, no horizontal overflow and no composer covering the editor.
3. **Visible adaptation and voice.** Preview actual saved/current text and attached media, including links, and label previews as approximations. Explain the supported publishing format without claiming to have inspected media. Compare actual variants. Replace generic or fact-inventing refinement chips with grounded editing instructions. Surface saved voice guidance and examples with a correction route; never invent provenance. Distinguish this-post instructions from lasting account preferences. Add reversible edits without cross-draft history leaks; persist any new history only through bounded owner-checked workspace fields.
4. **Anticipate requirements.** Show connected destination identity and missing connection/media requirements while drafting. Drafting for disconnected networks remains allowed. Offer explicit review of chosen eligible platforms while retaining other versions; never silently change selection. Put settings, exact approval and per-platform outcomes in the canvas. Translate waiting/uncertain states into clear next steps. Preserve immutable approval and failed-platform-only retry.
5. **Recovery and continuation.** Keep save success quiet; expose retry, copy and comparison with the saved version on failure/conflict. Do not reload away unsaved work. Retain attachment and conversation state on failure/reload. Prevent late responses and obsolete cards from crossing draft boundaries. Give returning customers real saved ideas and attention states, without fabricated activity or empty metric decoration.
6. **Coherent finishing.** Use readable type, consistent controls, visible focus, labelled inputs and at least 44px primary touch targets. Keep both Instagram options clear. Correct onboarding/Account voice status from saved evidence, not merely connection presence. Explain source/media inspection limits near the relevant controls. Retain all existing features through clear routes.

## Acceptance evidence

Run the existing security/persistence/publication suite plus meaningful regression checks for new state and route behaviour. Inspect desktop and 390px mobile with keyboard navigation; create, edit, compare, preview, save and reload a draft. Exercise failed generation/save/upload, concurrent save conflict, account ownership, partial results and immutable approval. Record exact checks and limitations. Verify no real providers or production mutations occurred.

Update the feature matrix, handoff and rollback instructions. Separate implementation, automated tests, browser observations, provider validation and deployment status. Do not raise scores based only on code existence. List unfinished work and external dependencies explicitly.

Recruit target creators for a subsequent study: at least 8/10 should create and find a useful saved draft without coaching; all should identify destination, content and time before approval; no participant should lose work in recovery exercises. Compare time, voice recognition and preference against their existing workflow. These are targets, not achieved results.
